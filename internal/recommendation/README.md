# Recommendation order and lifecycle

The rules offer source-backed manual guidance. A reviewed annual or cycle energy fact, usage answer and tariff can make an action eligible; those inputs alone do not establish savings. When a separately supported action scenario supplies a benefit, the response retains its period, currency, basis, and scenario evidence revisions.

The list orders active actions before candidates and candidates by evidence readiness. Actions with supplied benefits sort only within the same state, period, currency, and benefit basis; values from different scopes are not compared. Unknown-benefit actions retain their order and remain visible. Usage frequency is not treated as a saving, and the response does not drop actions because of a per-appliance cap or benefit-group de-duplication.

Owner events follow `active → accepted → completed`, or `candidate/active/accepted → snoozed/dismissed`. A snooze lasts at most 90 days and returns to the evidence-derived state on expiry. Dismissal of an active action can be reopened with `accepted`; completion is terminal for that rule version. The latest event is private to the home owner and requires a UUID idempotency key. Accepted actions stay visible; snoozed and dismissed actions move behind current opportunities. If evidence no longer supports a previously accepted action, the display state becomes `expired`; a new rule version shows `superseded`. Events do not themselves prove current energy benefit or measured outcome.
