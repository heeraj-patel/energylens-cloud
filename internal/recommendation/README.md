# Recommendation order and lifecycle

The current rules offer source-backed manual guidance. They have no comparable baseline/action scenario, so every `savings_amount` is null. A reviewed annual or cycle energy fact, usage answer and tariff make an action eligible; those inputs alone cannot establish the energy or money that changing a setting would save.

The list orders active actions before candidates. For active actions with the same confirmed usage unit, larger current household hours or cycles per week appear first. Different units are kept in a deterministic group order and **are not compared as benefits**. Candidates are ordered by evidence readiness. Per appliance, only the strongest action in a benefit group remains; the list is capped at three actions per appliance. This is an evidence and activity priority, not a numeric expected-benefit ranking. A future scenario rule needs a source-supported baseline, alternative, comparable units, current household usage and rate, with mutually exclusive scenarios handled before any expected benefit can drive cross-category ranking.

Owner events follow `active → accepted → completed`, or `candidate/active/accepted → snoozed/dismissed`. A snooze lasts at most 90 days and returns to the evidence-derived state on expiry. Dismissal of an active action can be reopened with `accepted`; completion is terminal for that rule version. The latest event is private to the home owner and requires a UUID idempotency key. Accepted actions stay visible; snoozed and dismissed actions move behind current opportunities. If evidence no longer supports a previously accepted action, the display state becomes `expired`; a new rule version shows `superseded`. Events do not themselves prove current energy benefit or measured outcome.
