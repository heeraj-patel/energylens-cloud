# Local auth foundation (inactive)

Migration 0044 stores one normalized email and Argon2id hash per local user, hashed email verification tokens, and hashed refresh sessions with a family ID and rotation link. Signup will create a stable `auth_identities` mapping with issuer `urn:energylens:local:v1` and the user UUID as subject. Email verification must precede any access or refresh token issuance; `users.email_verified` changes only after verification. Account deletion must revoke sessions and remove credentials through the user cascade.

`local_auth.go` provides bounded Argon2id hashing, 256-bit opaque token generation with purpose-separated SHA-256 storage hashes, and 15-minute EdDSA access tokens with fixed issuer, audience, subject, issue time, expiry, required `kid`, and credential access version. An explicit ring of at most eight public keys verifies signatures; an active private key must match the public key at its `kid` before signing. Rotation adds the new public key to every verifier before switching the active private key, retains the previous public key for at least the 15-minute access lifetime plus clock skew, and then removes it. Missing, retired, mismatched, or unknown keys fail closed. A verification-only instance needs no private key. No production key loader or public route is installed. Existing external OIDC authentication remains the only active runtime path.

Migration 0045 and `local_registration.go` add an inactive transactional signup/verification service. It stores HMAC keyed email/day and trusted-source/hour counters (3 and 10 attempts respectively), never raw rate keys. Valid requests receive the same public result for new, existing, deleted, and throttled identities. New local accounts use a stable issuer/subject mapping, keep the profile email unverified until a one-hour single-use challenge is consumed, and never merge with an external OIDC user by email. Resending invalidates prior challenges. The sender interface is unconfigured at runtime and tests use only a fake sender. Sender failure does not change the public response; a bounded retry can issue another challenge.

Migration 0046 and `local_login.go` add an inactive login service. It counts HMAC keyed account/hour and trusted-source/hour attempts (5 and 20), uses the same bounded Argon2id work for an unknown valid email, and returns one generic credential error for unknown, wrong-password, unverified, deleted, and throttled accounts. A valid verified account receives a 15-minute signed access JWT and a 30-day opaque refresh token whose SHA-256 purpose-separated hash alone is stored in a new session family. No login route or production signing/rate key is installed.

`local_refresh.go` rotates one refresh token at a time, revokes an entire family on replay, and supports idempotent family logout. Migration 0047 and `local_recovery.go` add inactive recovery: HMAC-only source/hour and email/day limits, generic accepted responses, one-hour one-use challenges, and a transactional password change that revokes every refresh session for the user. Recovery locks existing refresh families before the credential so rotation and reset serialize. Migration 0048 adds a per-credential access version; reset increments it in that transaction. The future local bearer verifier checks the signed version against the current verified, active account and stable local identity on every request, so prior access JWTs fail as soon as reset commits. Tests use only a fake sender.

Before enabling local authentication, add real verification and recovery mail delivery, protected production key provisioning and rotation deployment, local HTTP routes and client wiring, and a verifier dispatcher that accepts only the configured local and external issuers. The future HTTP edge must derive the rate source from a trusted client address, never from a caller-supplied forwarding header. Logout revokes refresh sessions; a previously issued access JWT remains valid until its 15-minute expiry unless a separate account-wide access invalidation is requested.
