# Local auth foundation (default off)

Migration 0044 stores one normalized email and Argon2id hash per local user, hashed email verification tokens, and hashed refresh sessions with a family ID and rotation link. Signup creates a stable `auth_identities` mapping with issuer `urn:energylens:local:v1` and the user UUID as subject. Migration 0096 permits immediate credential activation without claiming mailbox verification; `users.email_verified` stays false until a separate recovery challenge proves mailbox access. Account deletion revokes sessions and removes credentials through the user cascade.

`local_auth.go` provides bounded Argon2id hashing, 256-bit opaque token generation with purpose-separated SHA-256 storage hashes, and 15-minute EdDSA access tokens with fixed issuer, audience, subject, issue time, expiry, required `kid`, and credential access version. An explicit ring of at most eight public keys verifies signatures; an active private key must match the public key at its `kid` before signing. Rotation adds the new public key to every verifier before switching the active private key, retains the previous public key for at least the 15-minute access lifetime plus clock skew, and then removes it. Missing, retired, mismatched, or unknown keys fail closed. A verification-only instance needs no private key. The default runtime keeps existing external OIDC authentication alone.

Migration 0045 and `local_registration.go` add transactional signup and legacy verification support. Registration stores HMAC keyed email/day and trusted-source/hour counters (3 and 10 attempts respectively), never raw rate keys. In the email profile, only a new address receives an account and login-shaped session; existing addresses and throttled requests receive generic non-authenticated acceptance. Signup checks existing local credentials and account email values, including external OIDC accounts, before creating a user. The legacy verification challenge service remains for preexisting pending credentials; immediate signup does not send one.

Migration 0046 and `local_login.go` add a gated login service. It counts HMAC keyed account/hour and trusted-source/hour attempts, uses the same bounded Argon2id work for an unknown valid email, and returns one generic credential error for denied accounts. An activated or verified email credential receives a 15-minute signed access JWT and a 30-day opaque refresh token whose SHA-256 purpose-separated hash alone is stored in a new session family.

`local_refresh.go` rotates one refresh token at a time, revokes an entire family on replay, and supports idempotent family logout. Migration 0047 and `local_recovery.go` add recovery: HMAC-only source/hour and email/day limits, generic accepted responses, one-hour one-use challenges, and a transactional password change that revokes every refresh session for the user. Activated signup accounts can request recovery; consuming the mailbox challenge marks their address verified. Recovery locks existing refresh families before the credential so rotation and reset serialize. Migration 0048 adds a per-credential access version; reset increments it in that transaction. The bearer verifier checks the signed version against the current active account and stable local identity on every request, so prior access JWTs fail as soon as reset commits. Tests use only a fake sender.

`local_key_loader.go` loads a bounded explicit Ed25519 PEM ring from absolute regular files owned by the service user, with a non-symlink private file restricted to owner access. It rejects malformed, oversized, mismatched and group/world-writable keys. It also reads three separate 32-byte private rate keys. The resulting codec is an immutable deployment snapshot; key rotation requires a restart with the new key ring. `dual_verifier.go` selects the configured OIDC or local verifier by untrusted issuer only to choose a validation path. It never falls back after a selected verifier rejects the token, and it checks the returned issuer. `app.Build` uses OIDC alone by default, local verification alone when local auth is explicitly enabled without OIDC settings, or the dual verifier when both complete configurations are present.

`local_mail.go` provides a gated Resend adapter for verification and reset mail. A separate API-side `ENERGYLENS_CLOUD_LOCAL_AUTH_MAIL_ENABLED` flag defaults off; `BuildLocalAuthSender` returns no provider while disabled. Its API key, sender and HTTPS link origin are separate from worker-only report mail. It sends plain text with a fixed path and a one-hour token in the URL fragment, never a query string, and uses a purpose-separated token hash as the provider idempotency key. Transport failures have generic errors; registration/recovery continue to return generic accepted outcomes. Deployment must verify that provider/domain click and open tracking are disabled, and the future client must consume and clear the fragment before third-party requests. Tests do not send provider mail.

`local_http.go` mounts first-party auth operations only when the complete service set is ready. Bodies require strict JSON under 4 KiB; responses disable caching and referrers. Registration, login, and recovery rates use the immediate socket peer by default. `LocalAuthSourcePolicy` can instead accept exactly one `X-Forwarded-For` address when that peer belongs to an explicitly configured `ENERGYLENS_CLOUD_LOCAL_AUTH_TRUSTED_PROXY_CIDRS` range. It rejects absent or multi-hop forwarded values; untrusted peers cannot supply a rate source through a header. The edge must append the actual client address, and network access to the API must be limited to the configured proxies before using this setting. The shared OpenAPI manifest marks these paths gated. A PostgreSQL HTTP round trip covers immediate signup through reset without sending email.

`ENERGYLENS_CLOUD_LOCAL_AUTH_ENABLED` defaults false. When true, startup requires an API role, database, enabled dedicated local mail, an Ed25519 private key file, a JSON map of trusted public key IDs to absolute PEM paths, an active key ID, an audience, and three independent binary rate key files. OIDC may be absent; if any OIDC setting is present, issuer, audience, and JWKS URL must all be present. The OIDC issuer cannot equal the fixed local issuer, and the two configured audiences must differ. The environment names are `ENERGYLENS_CLOUD_LOCAL_AUTH_PRIVATE_KEY_FILE`, `ENERGYLENS_CLOUD_LOCAL_AUTH_PUBLIC_KEY_FILES`, `ENERGYLENS_CLOUD_LOCAL_AUTH_ACTIVE_KEY_ID`, `ENERGYLENS_CLOUD_LOCAL_AUTH_AUDIENCE`, and `ENERGYLENS_CLOUD_LOCAL_AUTH_{REGISTER,LOGIN,RECOVERY}_RATE_KEY_FILE`. Startup rejects missing, unsafe or duplicate key material. The gate installs both local routes and the database-backed local verifier; disabled deployments open no local key files and keep returning 404 for local routes.

An operator can run `energylens-cloud check-local-auth-keys` with the proposed API environment loaded. It validates the complete API configuration and exact file-backed keys without connecting to PostgreSQL, binding a listener, or sending mail. It exits unsuccessfully when the gate is off or any material is unsafe. Key files must be absolute, regular, owned by the service user, and inaccessible for group/other writes; private and rate key files must also be inaccessible for group/other reads. Rate keys are exactly 32 raw random bytes in three separate files. `ENERGYLENS_CLOUD_LOCAL_AUTH_PUBLIC_KEY_FILES` is a JSON object of key ID to absolute public PEM path, for example `{"current":"/private/keys/current.pub"}`. Never commit actual key material or private environment files.

For a signing key rotation, distribute the new public key to every API instance while retaining the old public key under its original ID. Keep a separate, pinned copy of the old public key and check each proposed snapshot with `check-local-auth-keys --retain-key-id OLD_ID --retain-public-key-file /absolute/path/to/pinned-old-public.pem`; the reference cannot be the candidate key file or a hard link to it. This rejects removal or changed bytes for the old key. Switch the active private key and ID only after the new public key is trusted everywhere, and restart each instance with the validated snapshot. Keep the old public key for at least the 15-minute access token lifetime plus clock skew after the last old signer stops. Then remove it in a later snapshot. Do not rotate the three rate keys during signing key rotation: replacing them resets the effective rate-limit history. The check is local to one snapshot; deployment order and elapsed retention time require operator verification.

Before enabling the gate in a deployment, provision and test production key rotation, wire the client flows, verify mail provider tracking settings, and verify the deployed proxy's append behavior and API network restriction before configuring trusted proxy ranges. Logout revokes refresh sessions; a previously issued access JWT remains valid until its 15-minute expiry unless a separate account-wide access invalidation is requested.
