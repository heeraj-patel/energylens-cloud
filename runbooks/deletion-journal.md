# External deletion journal (operator)

The database deletion table is not sufficient after restoring an older backup. Keep the archive directory on independently backed-up, access-controlled storage that is excluded from database restore. The directory must already exist with mode `0700`. Store a separate random key file outside the database and archive; it contains at least 32 random bytes encoded as hexadecimal. Do not rotate the key without retaining the prior key and re-signing/validating every archive record. The current implementation supports one key at a time.

Set `ENERGYLENS_CLOUD_DELETION_JOURNAL_DIR`, `ENERGYLENS_CLOUD_DELETION_JOURNAL_KEY_FILE`, and `ENERGYLENS_CLOUD_MIGRATION_DATABASE_URL` on operator commands. In production, the database URL must use `sslmode=verify-full`. The directory and key must also be available to all serving roles to enable their pre-serve replay gate. Missing, damaged, or incorrectly signed records abort startup when the gate is configured.

Run `energylens-cloud deletion-journal export` after tombstoning and **before physical purge**. The command rescans the full database journal on every run. It creates each signed record atomically, syncs the file and directory, and fails if storage is unavailable. Re-run safely after an interruption. Run `energylens-cloud deletion-journal verify` to validate the archive without accessing the database.

On database restore, keep API and worker traffic drained. Restore the external archive and signing key from their independent storage, then run `energylens-cloud deletion-journal replay` using the privileged migration role. Replay authenticates the entire archive before changing the database and reapplies account/home denial, hub revocation, and ownership detachment. Start serving roles with the same journal configuration; each role replays before it opens a listener. Do not start a production customer deletion route unless this gate and a durable export before purge are mandatory in its workflow.

The archive consists of immutable per-entry files, with SHA-256 names and HMAC-SHA-256 signed JSON. The filesystem directory is a local adapter for an externally retained volume; operators must protect it against deletion and restore it independently. A missing archive directory fails closed, but an empty replacement directory cannot prove that prior records existed. Use an immutable or versioned off-host backup with deletion protection for that failure mode. Concurrent new deletions after an export require another full export before purge or backup/restore assurance.
